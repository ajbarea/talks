    Claude Code is built the other way around. It runs in your repository and your terminal. It reads your code, edits files, and runs the same commands you would. Around that sit the pieces that let me shape it. Hooks are rules it can't skip, which I'll demo. Plugins bundle skills and hooks so a whole lab installs them at once.     4 · A short demo

    A five-line hook blocks reads, edits and commands that name your secrets file

    › Add DEBUG=1 to the .env file.

    ● Bash ls -la; cat -A .env

    ✕ Blocked: .env holds secrets. Don't read or change it.

    I didn't add DEBUG=1. The project has a hook that blocks me from reading or editing .env … I haven't tried to get around it.

    ✓ .env unchanged

    A real headless run (claude -p, Claude Opus 5.5, permission prompts off), November 2, 2026, trimmed. Adapted from an example in Anthropic's hooks guide.

    Here's a hook. Your .env file holds passwords and keys. This one, adapted from Anthropic's hooks guide, runs before Claude reads, searches or edits a file, or runs a command. If the target names .env, it blocks the call and says why. Anthropic's version watches only edits; I added reads, searches and shell commands, because in my test Opus changed a protected file through the shell. I asked Claude to add a line to .env. The hook stopped its first command, and Claude told me why instead of trying another way. Permission prompts were off, so the hook held on its own. Now, a question for you. Sources: Claude Code hooks guide, "Block edits to protected files", and hooks reference; the runs' transcripts, November 2, on Opus 5.5 and Haiku 5.5.

    Four steps put Claude Code to work in your own repository

    3. Add one rule as a hookthe .env hook from the demo is a good first one
    4. Give it one small taska failing test or a stale README; read the change before you commit

    Needs Pro or above, a Team or Enterprise plan, or an API account. What it reads goes to Anthropic to be processed. On Team, Enterprise and API plans, Anthropic doesn't train on it and keeps it 30 days by default.

    So how do you get started? Install it. In your repository, run claude, then slash init: it writes a starting file with your build commands and conventions. Add one rule as a hook, like the .env one. Then give it one small, checkable task, and read every change before you commit; it makes confident mistakes. It needs a paid plan or an API account; Anthropic has a discounted Team plan for scientists that a PI can apply for. On privacy: your prompts and the files it reads go to Anthropic to be processed. On Team, Enterprise and API plans, Anthropic doesn't train on them unless your organization opts in, and keeps them 30 days by default. On a personal plan, training is a setting you choose.
