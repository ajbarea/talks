A five-line hook blocks reads, edits and commands that name your secrets file

› Add DEBUG=1 to the .env file.

● Bash ls -la; cat -A .env

✕ Blocked: .env holds secrets. Don't read or change it.

I didn't add DEBUG=1. The project has a hook that blocks me from reading or editing .env … I haven't tried to get around it.

✓ .env unchanged

A real headless run (claude -p, Claude Opus 5.5, permission prompts off), November 2, 2026, trimmed. Adapted from an example in Anthropic's hooks guide.

Your .env file holds passwords and keys. This hook, adapted from Anthropic's hooks guide, runs before Claude reads, searches or edits a file, or runs a command. If the target names .env, it blocks the call and says why. Anthropic's version watches only edits; I added reads, searches and shell commands, because in my test Opus changed a protected file through the shell. I asked Claude to add a line to .env. The hook stopped its first command, and Claude told me why instead of trying another way, with permission prompts off. Now, how to try these yourself.
